# План: `GetMeLegacy` и миграция на `Blocks`

`GetMe` остаётся основным методом и возвращает `*models.BotFullInfo`.
Номер версии пока не выбираем; тег и путь модуля не меняем.

1. **Подготовить рабочее место.** Создать отдельный worktree
   `.worktrees/getme-legacy` с веткой `feat/getme-legacy` от текущего HEAD
   и сохранить этот план в `docs/plans/` до изменения кода.
2. **Добавить `GetMeLegacy`.** Метод возвращает `(*models.User, error)` и
   помечен `Deprecated: Use GetMe.` Он вызывает `GetMe` один раз, сохраняя
   обработку ошибок и обновление активных имён бота. Вернуть в `User`
   девять прежних полей с исходными именами и JSON-тегами, включая
   `SupportInlineQueries`; пометить их устаревшими и заполнять из `BotFullInfo`.
3. **Защитить отправку цитат.** Вернуть `Text RichText` в обе модели
   раскрывающейся цитаты с пометкой `Deprecated: Use Blocks.` При чтении
   библиотека не заполняет `Text`. При отправке, если `Text` отличается от
   нулевого значения, а `Blocks` пуст, вернуть ошибку
   `Text is deprecated; use Blocks` вместо молчаливой потери содержимого.
   Если блоки есть, отправлять только `Blocks`, игнорируя `Text`.
   Описать это в changelog.
4. **Проверить миграцию.** Проверить прежние значения полей `User`, один
   запрос и маршрутизацию по алиасам. Для цитат подтвердить ошибку при
   отправке только `Text`, приоритет `Blocks` при наличии обоих полей и
   пустой `Text` при чтении. Запустить `go test -race ./...` и `go vet ./...`.
